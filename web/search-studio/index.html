    How search and the map work
    IndexExaminedFrontierMatches

    This sample indexes 1,992 public FMA recording records and audio-derived vectors. It is small and biased and does not represent mainstream music. Previews are verified from the approved source recordings during deployment. A recording can play only when this deployment publishes a verified same-origin preview for it.

    A paired CLAP model compares descriptions and audio in 512 dimensions. The map is a fixed approximate view; positions do not determine results, and islands are not learned genres. It draws every recording as a faint cloud and a bounded selection of actual points you can select; zooming in reveals more points and stored index connections. Use the list for every result.

    Sound similarity is not a relevance probability. Source genres are catalog labels; vocals, language and mood are not verified filters.

    The animation condenses actual HNSW candidate visits into a few trace-backed moments on this same catalog. Context lines are genuine stored index connections; the frontier shows the available candidate-queue snapshot, which is capped at 16 entries. The final focus reveals the exact displayed matches, not a trained confidence field. Exact scoring supplies results immediately. At this size an exact scan is already fast; the graph is an explanation of the index, not a claim of acceleration.

    More artists is an optional display policy: it prefers one recording per source artist within the returned sound candidates, then fills remaining places from that same pool. Paging and refinement never fetch deeper sound results. The first sound match and every original similarity score are preserved. This trades some sound similarity for artist breadth; it is not a measured relevance improvement.

    Language, instruments, vocals and mood are not independently verified constraints. A phrase such as “no vocals” is a preference, not a guaranteed filter.
